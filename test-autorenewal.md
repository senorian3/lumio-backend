# Тестирование логики автосписания

## Изменения, внесенные для улучшения автосписания:

### 1. Обновлен метод поиска активных подписок

**Файл**: `payments.repository.ts`

- Добавлена проверка `nextPaymentDate > now()` или `nextPaymentDate === null`
- Теперь активной считается подписка, у которой:
  - `status: 'successful'`
  - `autoRenewal: true`
  - `cancelledAt: null`
  - `nextPaymentDate > now()` или `nextPaymentDate === null`

### 2. Улучшен обработчик рекуррентных платежей

**Файл**: `process-recurring-payment.command-handler.ts`

- Добавлен `AppLoggerService` в конструктор
- Добавлено подробное логирование каждого этапа:
  - Начало обработки инвойса
  - Поиск существующего платежа
  - Создание нового платежа
  - Обновление статуса предыдущего платежа
  - Создание сообщения для Lumio

### 3. Логика автосписания в Stripe

**Как работает**:

1. Stripe отправляет webhook `invoice.paid` при успешном автосписании
2. `StripeHookCommandHandler` обрабатывает событие и вызывает `ProcessRecurringPaymentCommand`
3. `ProcessRecurringPaymentCommandHandler`:
   - Находит существующий платеж по `subscriptionId`
   - Создает новый платеж с обновленными датами периода
   - Обновляет статус предыдущего платежа на `COMPLETED`
   - Отправляет сообщение в outbox для обновления подписки в Lumio

## Проверка корректности данных в БД:

### Поля, которые должны обновляться при автосписании:

1. **Новый платеж**:
   - `subscriptionId` - тот же, что и у предыдущего платежа
   - `periodStart` - начало нового периода (из инвойса Stripe)
   - `periodEnd` - конец нового периода (из инвойса Stripe)
   - `nextPaymentDate` - дата следующего платежа (= `periodEnd`)
   - `status` - 'successful'
   - `autoRenewal` - копируется из предыдущего платежа

2. **Предыдущий платеж**:
   - `status` - обновляется на 'completed'
   - `autoRenewal` - устанавливается в `false`

## Тестовые сценарии:

### Сценарий 1: Успешное автосписание

1. Stripe успешно списывает платеж
2. Отправляется webhook `invoice.paid`
3. Создается новый платеж в БД
4. Предыдущий платеж помечается как `completed`
5. Отправляется сообщение в Lumio

### Сценарий 2: Подписка отменена (`autoRenewal: false`)

1. Stripe не должен списывать платеж
2. Если все же пришел webhook - нужно проверить обработку

### Сценарий 3: Просроченный платеж

1. Stripe пытается списать, но платеж не проходит
2. Отправляется webhook с другим статусом
3. Нужна обработка failed платежей
